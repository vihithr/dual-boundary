# 双边界 · dual-boundary

一个帮编程 Agent 判断模块该不该拆、循环依赖该不该解、接口值不值得加的架构评审技能。它同时看两件事：一次改动会牵动哪些模块，以及读代码的人要去几个地方才能理解同一个行为。

## 怎么用

把整个仓库克隆到 Agent 的技能目录，保留 `dual-boundary` 目录名。如果你的 Agent 支持直接读取本地文件，也可以让它读取本仓库的 [SKILL.md](SKILL.md)，然后给它一个具体问题。

例如，在待评审项目里问：

> 用 dual-boundary 看一下这两个互相引用的包。指出具体是哪两条依赖、在什么粒度上成环，再判断抽一个 shared 包值不值得。

> 我把启动流程拆成了五个文件。对照改动前后，看看现在要从哪里才能读出完整的注册顺序。
